# Server-authoritative state machine with field locking

We model every Shipment as a server-authoritative state machine: `DRAFT→BOOKED→PICKED_UP→IN_TRANSIT→OUT_FOR_DELIVERY→DELIVERED`, plus FAILED_ATTEMPT, RETURNING, RETURNED, CANCELLED. Only valid transitions are allowed. The moment a Shipment enters an active Run-sheet, its mutable fields are locked to merchants/customers until the driver syncs or checks it back into a Hub; unlocked free-form fields converge by last-write-wins.

We chose this over a full CRDT merge across devices and over per-field versioned optimistic concurrency with client aborts. A CRDT is overengineered for a shipping domain where status is a closed machine owned server-side and almost everything else is a free-form note. Versioned concurrency adds ledger weight for little gain. Field locking resolves the state-overwrite hazard raised during design (e.g. customer edits address while a driver marks a failed delivery offline). This is hard to reverse because the sync module, dispatcher, and all status-updating clients depend on the machine and its locks; it's surprising because most "offline-first" systems assume multi-writer convergence.
