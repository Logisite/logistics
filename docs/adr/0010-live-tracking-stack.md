# Live tracking stack: MapLibre, free tiles, POST ingest, dual fan-out

Live vehicle tracking renders on **MapLibre GL JS** (MIT fork of Mapbox GL, keyless) with tiles from **OpenFreeMap's** public instance: unlimited views, no registration, OSM data; a per-operator `MAP_TILES_URL` makes branded or self-hosted tiles (Protomaps PMTiles) a deployment choice. Driver phones **ingest via batched HTTP POSTs every 5–10 seconds during active runs** into the existing `gps_positions` table, deliberately not WebSocket ingest, because mobile networks punish long-lived sockets and batched POSTs retry cleanly through the offline ledger. Fan-out splits by audience: authenticated **WebSocket rooms** (`run:{id}`) for staff dashboards, and unauthenticated **SSE streams behind signed capability links** for customer tracking pages. Markers animate client-side between sparse server points.

We chose this over Google Maps and Mapbox rendering (per-load billing and lock-in against a £0/month unlimited baseline), over polling (worse UX at equal cost), and over WebSocket-for-ingest (fragile on mobile). Total recurring infrastructure cost is £0 at any foreseeable scale; the only honest future spend is tile bandwidth if an operator outgrows the free instance, at which point PMTiles-on-own-storage converts map hosting into pennies of bandwidth. It is hard to reverse because the SSE contract and room topology become the public tracking surface customers depend on. It is surprising because the customer-facing live map requires no account, no app store, and no vendor relationship, just a signed link and a browser. Geocoding stays on the existing low-volume Mapbox token with Nominatim noted as a self-hosted fallback; rendering never depends on it.
