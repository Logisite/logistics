# Autonomous OpenAPI via defineRoute

We generate `openapi: 3.1.0` from a single `OpenAPIRegistry` (`apps/api/src/openapi/registry.ts`) with a helper `defineRoute(c){registry.registerPath(c); return c}`. Every router defines its Zod schema once at top level and calls `defineRoute` there so `import '../customers/router.js'` registers the path at import time; the same object is reused for `parse(schema, req.body)` validation and for `OpenApiGeneratorV31` to emit `apps/api/openapi.json` via `apps/api/src/openapi/generator.ts` which side-effect imports all routers.

We chose this over hand-maintained `openapi.json` and over a framework switch to Fastify/`express-zod-api` because it keeps Express, keeps existing `supertest` suites, and makes `GET /openapi.json` (public for Redoc/Postman/`openapi-typescript`) and `GET /docs` (Swagger UI gated `AUDIT_READ`) grow automatically with router surface — drift is impossible without remembering a second file. It is hard to reverse because `generateSpec()` is the only writer of `openapi.json` and every new route must call `defineRoute`; it is surprising because the fastest way to add an endpoint looks like just `router.post`, but the durable path is `defineRoute` first, then `router.post` reusing the same schema.
